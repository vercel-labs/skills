### B. Stop collapsing namespace identity back to bare names

Several current implementation choices undermine the feature’s core purpose:

- `discoverSkills()` still deduplicates by `skill.name`, not namespace-qualified identity.
- `getAllLockedSkills()` converts composite keys into a map keyed only by name, so same-name entries overwrite one another in that returned map.
- `removeSkillFromLock()` and `getSkillFromLock()` fall back to the first name match across namespaces.
- Migration selects `entries[^1_0]` when multiple entries match a skill name.

Those behaviours conflict with the intended coexistence of, for example, OpenAI and Anthropic skills having the same name. That coexistence is the central requirement in \#2640.[^1_1]

Recommended invariant:

```text
Identity = scope + namespace + name
```

Carry that identity through discovery, installation, locking, listing, updating, and removal. A bare-name selector should work only when it identifies exactly one candidate; otherwise return an explicit ambiguity error.

Separately deduplicate repeated discovery of the same physical skill path. “Same path encountered twice” and “different skills sharing a name” are different problems.
